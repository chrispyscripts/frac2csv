**Sanjel: a stage that prints a clock but no day is no longer exported in the year 2000.** 00100's interval 19 heads its page "January 0, 1900" — Excel's way of printing an empty date — which the reader refuses, and rightly: believing it once put a stage a century off. But that page's TIME axis is perfectly good, running 20:37 to 21:22. Only the day was ever missing, and losing the day lost the clock with it, because a stage is placed by a full timestamp. So the stage exported as **2000-01-01 20:37:16**, and in a CSV sorted by time that row sorts above the whole job.

**That one bad date was also causing the overlap.** A stage sitting in the year 2000 is no longer between its neighbours on the clock, so the hand-over trim — which cuts a chart where the next one begins — could not pair it with them. On 00100 it trimmed 22 charts instead of 24 and left stage 18 running straight into 19. Give the stage its real day and both go: **all 29 stages dated, 24 charts trimmed, and not one overlapping pair in the exported CSV.**

The day is taken only where it cannot be anything else — the dated charts either side must agree on the day, and this chart's clock must fall between theirs. Interval 18 is 19:57 and 20 is 21:19 on 2016-01-28, and 20:37 sits between them. A chart whose clock falls outside its neighbours' has wrapped past midnight, and that is a guess rather than a reading, so it is left undated. The time is never rewritten; only the day is filled.

**Liberty: a chart whose last clock label is lost no longer exports half its stage.** 00918 p159 prints three labels along a frame ruled for a full hour. The page has no text layer so every label is read by OCR, which returned only the first two — and the export window then fell back to the span *between those two labels*: 1800 seconds, half the sheet. All four channels on that page carry ink to 3217 seconds and everything past 1800 was thrown away. The window is now taken from the plot frame, calibrated on the gridline each label names. That also repairs the slope, which is the wider damage: a fit through the raw label boxes ran 4.65% fast on 00914, so every timestamp on the page drifted, not just the end of the window.

**"Lots of time errors that appear to be false flags" — they were all false.** 00009 has 38 charts; 23 carry a clock and 15 do not, and a chart with no time read is written 00:00:00. All fifteen landed on one instant and thirteen were reported as starting before the stage before them finished. Nothing was wrong with those clocks; there was no clock. The Lab now knows the difference and says nothing about a stage that never had one. A chart that genuinely starts at midnight is still checked, and a real overlap still reports.

**The end-trim switch moved up beside the chart.** It decides what the export contains, so it belongs above the chart rather than on a note in the legend. It appears only on a chart that actually has a trimmed end, and it says what it costs: those minutes then appear twice, here and on the stage they were handed to.

**Stacked view: the stage and the day, above the charts.** A stacked window is opened to read one stage closely, and the only things naming it were the tail of a long file name and a grey line where the date ran on into a sample count. Both are still there; the two that matter now have their own line.

**Dropping a file list is no longer slow to resolve on some machines.** Finding a list's folder used to try every drive letter from A to Z. A letter with no drive behind it is not free to ask about — and one mapped to a server that is gone can take tens of seconds — so a list could sit there long enough for the app to give up on it. It now asks Windows which drives exist and skips the network ones.

**Which templates this release touches:** the **Sanjel** and **Liberty** readers, and the Lab. Every other template reads exactly as it did under v1.11.31.
