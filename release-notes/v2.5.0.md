**The saved LAS now carries a log's Porosity and Grain Size columns as curves.**

**Porosity**
- **POR (%)** is where the Porosity column's bar ends. Most logs draw it on 8 cells of 3 % (0-24 %). The scale is read from each log's own labels.
- On 10,723 samples, 92 % read within 3 points of the porosity % in the log's own descriptions.

**Grain size**
- One curve per grain-size cell on the most common set: **GS_1_16MM, GS_1_8MM, GS_1_4MM, GS_1_2MM, GS_1MM** (very fine to very coarse sand). A filled cell reads 1 and an empty cell reads 0.
- Logs labelled another way are put on the same set. That includes vf..vc, Very Fine.., two-cell L-U labels, spelled-out ranges and reverse order.

**How the rows line up**
- Rows start at the log's top, so they line up with the rock column and the printout. Each row repeats over its step.
- A row with no filled cell is null.
- The LAS depth range stretches to take in every filled row.
- The curves themselves are unchanged. On 597 logs every curve value is the same as in v2.4.0, and logs with no cells save byte for byte as before.

**Left out, and the LAS says so**
- Porosity columns labelled as grades (Excellent .. Very Poor), about 12 % of logs. How a grade maps to a % is still an open question.
- Grain columns whose labels do not fit their cells.
- Micritic, silt and 2 mm cells, which have no standard curve.
- A LAS read from a printout PDF has no cells yet.

**Checked**
- The Python tests pass, including the tests that need the WellSight drive, and so do the Lab's JS tests.
- The cells were checked on 597 logs from the drive and against their printouts.
- Not yet tested on Windows itself.
