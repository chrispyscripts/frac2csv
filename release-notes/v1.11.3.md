**Fix in box.** Where a curve jumps to something that is not the curve, drag a box round it and that stretch is read again off the page underneath. The spikes are not the reader inventing numbers &mdash; measured over one of your STEP charts, all 3,860 samples sit on real ink &mdash; they are the reader following the *wrong* ink, a second mark of the same colour in the same column: a gridline, the fuzzy edge of the curve next to it, a legend swatch. Both are really there, and no rule tells them apart on every report. You looking at the page does, in one drag. The pen's colour is taken from the curve just outside the box, where the reading is good, so another curve crossing the same box is not picked up by mistake. The correction is saved against that file, stage and curve, and goes back on every time the file is read again; the legend says when a chart is carrying one. Undo puts it back. Needs the original page showing, since that is the ink being read.

**A stage that hands its tail to the next one now shows it.** Where a chart runs on past its own stage, the export cuts it there, because the next chart re-plots the same minutes and nothing should be written twice. The chart was being cut in the same place, so against the printed page it looked like the end had been dropped. It had not: on one well, every cut minute is re-plotted by the next stage, to the second. Those minutes are now drawn in grey dashes with a note saying which stage they went to, so the chart ends where the page does.

**The Lab was serving results from older versions.** The stored results are keyed by the file and by the reader that read it, so a new version is supposed to read everything afresh. In the built app it never did: it looked for the reader files on disk to tell versions apart, and the Windows build has none to find, so every version looked identical to every other. Results read months ago were still being handed back. This is why the chart handover, which shipped in 1.10.0, only appeared for you this week &mdash; and why it looked like five report types had all broken at once when they had not changed at all.

**Sanjel reports with an empty date.** One page prints "January 0, 1900" &mdash; the date cell was left blank and that is how the spreadsheet writes nothing. Read literally it put that stage a century away from the rest of the well, and the stages either side lost the most time on the page to the handover. A date that is not a day on the calendar is now treated as no date at all.

**Four windows no longer fight for the machine.** Dropping a file in each of four Lab windows started four whole reads at once and took the computer with it. They queue now. The same work happens in about the same time, and the machine stays usable while it does. The pulsing marks on a chart also stop pulsing while a window is behind another one.
