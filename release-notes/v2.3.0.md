**Mudlog printouts read from the PDF alone: drop a printout with no log file and it opens as a log.**

**A printout on its own**
- Drop a mudlog printout PDF on its own, with no .sl6 / .hl6 log file beside it. Frac2CSV reads it the way a person reads the page and opens it like a WellSight log:
  - the curves, read off their drawn lines, each named and scaled by its own caption;
  - the rock column, symbols, and slide / core runs, each named by the printout's own legend;
  - the header page's fields, the geologist's notes, and the log's columns.
- The PDF itself is stitched underneath as the printout, so every data set sits over the column it was read from.
- **Save LAS** writes a LAS of the curves as read, with the header, notes, rock types, symbols and show zones as CSV files, and the whole reading as JSON.
- Readings off a drawn line are good to about 1% of the scale's width. A reading past twice its printed scale is not on the printout at all, and the Lab says so.
- Only a PDF the frac readers find nothing in, with depth labels running on from page to page, is read this way. Frac reports read exactly as before.

**How well it reads**

Every log on the WellSight drive has an answer key, written from the log file. The PDF reader was marked against it on 302 printouts (every 28th), out of 1. "First reading" is the reader before this release's fixes, marked the same way. The last column is the app, which has no library of other printouts' legends (see Not yet):

| Part | First reading | Now | In the app |
|---|---|---|---|
| Header | 0.87 | 0.97 | 0.97 |
| Curves | 0.86 | 0.88 | 0.88 |
| Rocks | 0.92 | 0.92 | 0.90 |
| Symbols | 0.98 | 0.98 | 0.89 |
| Slide and core runs (29 logs) | 0.96 | 0.96 | 0.69 |
| Notes | 0.95 | 0.95 | 0.95 |
| Columns | 0.86 | 0.96 | 0.96 |
| **Overall** | 0.90 | 0.95 | |

Medians are higher: curves 0.92, symbols and columns 1.00.

**What changed in the reading**
- **Columns:** titles are read from the boxed header row over the columns only, no longer from the boxes above it. A title wider than its narrow column is read whole ("Slide", not "lid").
- **Header:** values that run on to a second or third line, a label split over two lines ("Bottom Hole / Coordinates:"), values set apart from their label, and labels with no colon are all read.
- **Curves:** the log starts below the header row, so legend lines there are no longer read as readings. A curve drawn with one line (older LogViewer printouts) is followed past the scale's end where the PDF keeps the line beyond the track's edge, and a scribble across the track is no longer taken for a wrap.
- **Fairer marks:** the answer key now records which of a log's curves its printout prints, and only those are marked. A rock the log names with a code of its own (a formation, like "Bakken") is left out, since its printout can only show the pattern.

**Not yet**
- Pictures a printout's legend leaves out cannot be named in the app. Some legends omit the slide and oil-show symbols, and TVD gamma logs print no legend at all. A library built from other printouts' legends names them in testing (symbols 0.89 to 0.98, slide runs 0.69 to 0.96), but it is made from client printouts, so it is not in the app.
- Horizontal logs write their descriptions beside the cross-section's survey labels; these come out mixed in the notes, so samples are not yet read from them.
- Logs with many curves (wireline sections, drilling data with no captions) still read poorly.
- Only LogViewer printouts have been tried. PDFs from other mudlogging programs are untested.

**Checked**
- 1,679 Python tests and the Lab's JS tests pass, run with the WellSight drive.
- Frac reading is unchanged. On the 77 frac reports of the 2026 set, none opens as a mudlog: every report the frac readers read is read as before, and one completion form they find nothing in still says so.
- Checked in the Lab on two sample printouts, vertical and horizontal: curves, rocks, symbols, header window and Save LAS.
- Not yet tested on Windows itself.
