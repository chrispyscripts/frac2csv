**26 Liberty charts were failing on a file where nothing was actually wrong (#691).**

Liberty prints two plots per stage: a treatment plot with a wall clock on its time axis, and a chemical plot that captions its axis "Time (min)" and prints elapsed minutes instead.

The reader worked out which way a chart is drawn by looking at where its clock labels spread. A chemical plot has no clock labels, so it was treated as a rotated page, the minutes were looked for down a column that does not exist, and the page was thrown away with "time labels not found". On 01004 that was 26 of 100 charts.

**No treatment data was ever lost** — all 50 treatment plots on that file read perfectly, and the chemical plots carry none of the four exported channels, so they are set aside either way. But 26 lines saying "Liberty chart failed" read like a quarter of the file going missing, which is exactly how it was reported.

Those pages now read: **99 of 100, up from 74.** The one that still fails is an honest one — OCR returned its right-hand time label as "Ss", leaving a single tick and nothing to fit.

Two smaller things were in the way, both because these pages have no usable text layer and have to be read by OCR: the caption comes back as two separate pieces, "Time" and "(min)", and an edge label can be swallowed by whatever sits next to it — that file prints 9 / 52 / 95 and the 9 comes back merged into the orange axis label beside it. Two labels are now enough to place the axis on an OCR'd page, which is what the clock axis has always allowed.

**An empty Tables tab now says why it is empty.** That filing is 252 pages, and the only page carrying text is the BC OGC cover form — every other page is a chart. There were no tables to miss, and nothing on screen said so.

Checked against the previous build on four other Liberty files: output identical, including the one this elapsed-minute path was originally written for.
