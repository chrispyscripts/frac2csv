**A fix file supplies the stage numbers, dates and times a report does not print (#813).**

Some reports leave out what the export needs. 00570 (AER Duvernay) prints no date on any of its 73 PRC plots, so every interval exported with no date. You can now give the app those values in a plain text file, one line per stage:

    # stage, date, time, page
    1, 2018-09-03, 00:14
    2, 2018-09-03
    7, , , p154

- **stage** is as the app names it.
- **date** is `2018-09-03` (`2018/09/03`, `03-Sep-2018` and `Sep 3 2018` also work).
- **time** is optional: 24-hour, the time at the chart's left edge.
- **page** is optional: the PDF page that charts this stage, for a page that prints no stage number.

A field left empty keeps what the app read.

**Where it goes:** name it after the report with `.fix.txt` on the end, for example `00570-100031806320W500_0486907_COMP.fix.txt`.
- With a file list, save it beside the report.
- Dragging PDFs into the Lab: drop it together with its report.

The extraction notes say what the file changed and list any line the app could not understand. Each changed chart also notes that its value came from the fix file. Editing the file re-reads the report rather than using the stored result. The full format is in `docs/fix-file.md`.

This is a first version of the user/fix mode, built on Carmine's description: "a text file that has stage number year date one line per stage or even for these odd case allow the text file to even say what page".

**Which templates this release touches:** none. Without a fix file every report reads exactly as it did under v1.11.50.
