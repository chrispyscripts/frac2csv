**A second filter, run on what the first one leaves.** The filter box now has a second slot: pick a filter, and a *then* appears with the same list beside it. The two run in order on the same curve, which is what the recommended pipeline actually is — strip the spikes with Hampel, then smooth what is left with Savitzky-Golay. Order matters and is kept, so Hampel-then-SG and SG-then-Hampel are two different settings and both are available. The second slot only appears once a first filter is chosen, because a filter with nothing to run on means nothing. A setting saved before this release still reads and runs exactly as it did.

**One chart can now disagree with the provider default.** Setting a default for a service provider used to make every chart under it read-only — you could see the setting but not get out of it on a single stage that needed something else. A chart's own setting now wins over the default, and *off* is a setting like any other, so one chart can be left unfiltered under a provider that filters everything. "Drop this chart's own setting" puts it back under the default.

**Fill in a table cell by hand.** Every cell in the tables window now highlights when you point at it and takes a click. Type, press Enter, and the value is yours; an empty cell shows a **+** so the cells most worth filling are the easiest to find. Edited cells stay marked in amber with a bar down the left, so at a glance you can always tell what the reader found from what you typed. Clearing a cell puts the sheet's own value straight back. Edits are held the way every other correction is and survive re-reading the same file, and what you type goes into the CSV.

**Halliburton IFS: the slurry rate is back on charts that were missing it.** On 00217 the rate axis is printed 20 / 15 / 10 / 5 / 0 and the page is read by OCR, which returned the 20 and the 15, misread the 10 as a 4 and returned nothing at all for the 5 and the 0. Two labels is below what the app requires to trust a scale, so the axis was thrown away and the rate went with it — on most of the file's charts. It is now recovered from where the ladder reaches zero: every scale on one of these plots runs the full height of the same frame, so they all reach zero at the same place, and a pair of labels that agrees with the rest of the page can be believed. **17 charts on that file gain their slurry rate, and no other reading on any chart of it moves by a single digit.**

**Halliburton IFS: the treating pressure is back where a tick mark was read as a digit.** On a filed-rotated page the tick stub above each number gets absorbed into it, so a pressure ladder printed 100 / 90 / 80 … comes back as 100, 805, 705, 60, 505 … Those corrupted numbers sit on a straight line of their own — five of them against four clean ones — so the app preferred them, read the axis as 105 to 805, and then correctly deleted both pressure channels as belonging to a scale no pressure could sit on. The chart shipped three curves instead of five and looked like missing data rather than a misread axis. Each label is now offered a second reading with its last digit removed, and it is kept only where that puts strictly more of the ladder on one straight line — so a ladder that already reads correctly can never be touched.

**STEP: a chart whose pressure was labelled "Main" now reports it as Treating Pressure.** The curve was always read, traced and scaled correctly; it simply arrived under a name the alias table did not know, so it was filed as an unrecognised extra and the Tr Press column came out empty. One word, and the chart that reported "No TR pressure" now carries it.
